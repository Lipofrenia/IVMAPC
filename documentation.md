# Документация проекта: Интернет-магазин компьютерной техники IVMAPC

Данный документ представляет собой полное руководство по архитектуре, кодовой базе и логике работы проекта. Он разработан для полного понимания того, как устроен магазин под капотом, и поможет вам как при защите проекта, так и при его дальнейшем развитии.

---

## 1. Что такое Django и как с ним работать

**Django** — это высокоуровневый веб-фреймворк на языке Python, который поощряет быстрое развитие и чистый, прагматичный дизайн. Главный принцип Django — *"Не повторяйся"* (DRY - Don't Repeat Yourself) и *"Батарейки в комплекте"* (огромное количество готового функционала из коробки).

### Архитектурный паттерн MTV
Django использует паттерн **MTV (Model-Template-View)**:
- **Model (Модель)** — отвечает за взаимодействие с базой данных (БД). Описывает структуру таблиц в виде Python-классов (ORM).
- **Template (Шаблон)** — HTML-файлы с динамическими вставками. Отвечает за то, *как* данные отображаются пользователю.
- **View (Представление)** — бизнес-логика. Python-функция, которая принимает HTTP-запрос от пользователя, обращается к Модели за данными и передает их в Шаблон для рендеринга ответа.

### Преимущества Django для этого проекта
- Встроенная мощная и легко настраиваемая **Админ-панель**.
- Встроенная система аутентификации (регистрация, вход, сессии).
- **ORM (Object-Relational Mapping)** — защита от SQL-инъекций "из коробки" и удобная работа с БД без написания SQL-кода.
- Удобная маршрутизация (`urls.py`).

## 2. Логика работы проекта (Жизненный цикл запроса)

Как все части проекта взаимодействуют между собой, когда пользователь, например, открывает страницу товара:
1. **Пользователь кликает по ссылке** товара (`/catalog/computers/core-x1/`).
2. Запрос попадает в корневой `ivmapc/urls.py`, который перенаправляет его в `shop/urls.py`.
3. В `shop/urls.py` находится маршрут, который вызывает соответствующий View (`views.product_detail`).
4. **View** обращается к **Model** (`Product.objects.get(...)`), чтобы вытащить информацию о товаре, его фото и характеристики из PostgreSQL.
5. **View** берет эти данные и передает их в **Template** (`product.html`).
6. Django подставляет переменные в HTML, и готовая веб-страница отправляется в браузер пользователя.

## 3. Детальное описание файловой структуры проекта

Проект разделен на логические директории. Рассмотрим каждый файл и его назначение.

### Корневые файлы
- **`manage.py`** — главная консольная утилита Django. Через нее мы запускаем сервер (`runserver`), создаем миграции (`makemigrations`), применяем их (`migrate`) и создаем админов (`createsuperuser`).
- **`.env`** — файл переменных окружения. Здесь хранятся секретные данные: пароль от базы данных, секретный ключ Django. **Этот файл никогда не заливается в GitHub** для безопасности.
- **`requirements.txt`** — список всех внешних Python-библиотек (Django, psycopg2, Pillow и т.д.), необходимых для запуска проекта.

### Папка `ivmapc/` (Конфигурация проекта)
Это "сердце" настроек.
- **`settings.py`** — глобальные настройки. Подключение БД (PostgreSQL), настройка путей к статике (CSS/JS) и медиа (загруженные картинки), языковые параметры (русский), регистрация нашего приложения `shop`.
- **`urls.py`** — корневой диспетчер URL-адресов. Он направляет пути `admin/` в админку, а все остальные — в приложение магазина (`shop.urls`).
- **`wsgi.py` / `asgi.py`** — шлюзы для развертывания проекта на реальном боевом сервере (через Gunicorn или Daphne).

### Папка `shop/` (Логика приложения магазина)
Здесь написан весь наш код.
- **`models.py`** — структура базы данных. Здесь классы Python превращаются в таблицы PostgreSQL.
- **`views.py`** — обработчики страниц. Здесь написаны функции для Главной страницы, Каталога, Корзины, Регистрации и т.д.
- **`urls.py`** — локальный маршрутизатор. Связывает URL (например `/basket/`) с конкретной функцией из `views.py`.
- **`admin.py`** — настройка того, как модели из `models.py` будут выглядеть и редактироваться в Админ-панели.
- **`context_processors.py`** — функции, которые работают перед загрузкой *каждого* шаблона. Например, наша функция здесь считает количество товаров в корзине, чтобы значок корзины с цифрой отображался в шапке на всех страницах сайта.
- **`templatetags/shop_tags.py`** — наши кастомные функции для HTML-шаблонов. Например, фильтр `format_price`, который превращает число `81900` в красивую строку `81 900 ₽`.
- **`management/commands/load_initial_data.py`** — наш кастомный скрипт для автоматического заполнения пустой базы данных тестовыми товарами и категориями при первом запуске.

### Папки Frontend'а
- **`templates/`** — все HTML-страницы проекта. Они наследуются от `base.html` (в котором лежит общая шапка и подвал), чтобы не дублировать код.
- **`static/`** — неизменяемые файлы дизайна: CSS-стили, JS-скрипты, системные иконки (SVG), шрифты.
- **`media/`** — изменяемые файлы: картинки товаров, загруженные через админку.

## 4. База данных: Описание таблиц (`models.py`)

Архитектура базы данных спроектирована так, чтобы магазин был масштабируемым.

1. **`Category` (Категории)**: Хранит разделы магазина (Компьютеры, Мониторы). Имеет поле `slug` для создания красивого URL (например, `/catalog/monitors/`).
2. **`Product` (Товар)**: Главная сущность. Связана с категорией (ForeignKey). Хранит название, цену, остаток на складе (`stock_quantity`), флаг "В наличии" и описания.
3. **`ProductImage` (Фотографии)**: Позволяет прикрепить к одному товару бесконечное количество фотографий. Одно из фото помечается как `is_main` (главное).
4. **`SpecGroup` и `ProductSpec` (Характеристики)**: Сложная система характеристик. Группы (например, "Процессор") включают в себя параметры ("Количество ядер", "Частота"). 
5. **`QuickSpec` (Быстрые характеристики)**: Короткие параметры, которые выводятся прямо под ценой (например: "Intel Core i5 / 16GB / RTX 4060").
6. **`SliderSlide` (Слайдер)**: Управление большими баннерами на главной странице (картинка, заголовок, ссылка).
7. **`CartItem` (Корзина)**: Хранит товары, добавленные в корзину. Может привязываться либо к зарегистрированному `User` (пользователю), либо к `session_key` (если человек не авторизован).
8. **`Order` и `OrderItem` (Заказы)**: Когда человек оформляет корзину, создается `Order` (заказ с общей суммой и статусом) и множество `OrderItem` (конкретные товары внутри заказа, причем цена фиксируется на момент покупки).
9. **`UserProfile` (Профиль)**: Расширяет стандартного пользователя Django, добавляя ему телефон и аватарку.

## 5. Полное руководство по запуску с нуля

Если вам нужно перенести проект на другой компьютер, выполните следующие шаги:

1. **Установка ПО**: Установите Python (3.10+) и PostgreSQL.
2. **База данных**: В консоли PostgreSQL создайте базу:
   `CREATE DATABASE ivmapc;`
3. **Виртуальное окружение**: Откройте терминал в папке проекта и создайте изоляцию:
   `python -m venv venv`
   Активируйте: `venv\Scripts\activate` (Windows)
4. **Зависимости**:
   `pip install -r requirements.txt`
5. **Структура БД (Миграции)**. Эта команда читает `models.py` и создает реальные таблицы в PostgreSQL:
   `python manage.py migrate`
6. **Заливка тестовых данных**. Чтобы не забивать товары вручную, мы написали скрипт:
   `python manage.py load_initial_data`
7. **Создание Админа**:
   `python manage.py createsuperuser`
   (придумайте логин, почту и пароль).
8. **Запуск сервера**:
   `python manage.py runserver`
   Сайт доступен по адресу: `http://127.0.0.1:8000/`

## 6. Руководство по работе в Админ-панели

Для управления сайтом перейдите по адресу: `http://127.0.0.1:8000/admin/` и введите данные, созданные на этапе `createsuperuser`.

### Раздел "Товары"
При добавлении нового товара вы увидите удобный интерфейс.
- Основные данные: Название, цена, количество на складе.
- **Инлайны (Вложенные формы)**: Благодаря настройкам в `admin.py`, прямо на странице редактирования товара вы можете загружать к нему картинки (Product Image), добавлять "Быстрые характеристики" и создавать целые блоки полных характеристик (Spec Groups). Все это делается на одном экране.
- **Остатки**: Если вы поставите `stock_quantity = 0`, товар автоматически получит статус "Нет в наличии" на сайте (благодаря свойству `stock_status` в моделях), а кнопка добавления в корзину может быть заблокирована.

### Раздел "Слайды"
Позволяет менять главный баннер сайта. Вы можете загрузить картинку, вставить ссылку (куда перейдет пользователь при клике) и менять порядок слайдов с помощью поля "Порядок" (Order).

### Раздел "Заказы"
Здесь появляются все оформленные покупки.
- Вы можете менять статус заказа: *Новый -> В обработке -> Отправлен -> Доставлен*. 
- Изменение статуса сразу отобразится у пользователя в его личном кабинете на сайте.
- Внутри заказа виден список купленных товаров (он защищен от редактирования, чтобы сохранять историческую точность чека).

## 7. Безопасность и продвинутые фишки

1. **Защита от SQL-инъекций**: Использование Django ORM означает, что все запросы к базе данных автоматически экранируются на уровне драйвера (psycopg2). Прямых SQL-запросов в коде нет, взломать БД через формы ввода невозможно.
2. **CSRF Защита**: Во всех HTML-формах (`<form>`) установлен тег `{% csrf_token %}`. Он защищает пользователей от межсайтовой подделки запросов (когда злоумышленник пытается выполнить действие от лица авторизованного пользователя).
3. **Корзина для гостей**: Написана кастомная логика в `views.py`. Корзина работает даже без регистрации, привязываясь к сессионному ключу (`request.session`). При регистрации или входе сессия сохраняется.
4. **Сортировка и Фильтрация**: В каталоге (`category_detail` view) параметры из URL (например, `?sort=price_asc&price_min=50000`) на лету модифицируют QuerySet (запрос к БД), отсеивая лишние товары на стороне базы данных, что экономит оперативную память сервера.
